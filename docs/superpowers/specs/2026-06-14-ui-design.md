# UI Design — PySide6 Settings & Status (Tray + Window)

**Date:** 2026-06-14 · **Status:** Approved

## Goal

A KDE-native PySide6 front-end over the existing engine: a system-tray app (Medal-style)
that runs capture in the background and exposes a settings/status window. The user edits
`Settings`, sees capture state + the last saved clip, saves clips / toggles recording from
the tray, opens the clips folder, and re-picks the capture source. Launched via
`python -m tea_clipper.ui`. The headless daemon (`python -m tea_clipper`) stays untouched.

## Architecture — Qt main thread + GLib worker thread

The engine is driven by a `GLib.MainLoop`; Qt has its own loop. Both run in one process:

- **Qt owns the main thread** (`QApplication.exec()`): tray, window, all widgets.
- **A daemon worker thread owns the `GLib.MainLoop`** and the `Controller`. `build_controller()`
  blocks on portal negotiation (its own GLib handshake, possibly a picker dialog), so it
  *must not* run on the UI thread.
- **UI → engine** actions are marshalled onto the GLib thread via `GLib.idle_add`.
- **engine → UI** updates come back as Qt signals (queued connections are thread-safe).

This is approach **A** from brainstorming (chosen over a single-thread `QTimer` GLib pump and
over a separate daemon subprocess).

## Components

**`ui/engine_host.py` — `EngineHost(QObject)` (unit-tested with a fake builder).**
The *only* place threading lives. Owns the worker thread + `Controller` lifecycle.
- Construction takes `settings`, a `config_path`, and an injectable `builder`
  (defaults to `controller.build_controller`) so tests pass a fake.
- `start()` spawns the worker thread → `builder(settings)` → persist restore token via
  `settings.save(config_path)` → `controller.start()` → run `GLib.MainLoop`. Emits
  `state_changed`. Build failure → `state_changed("Error", msg)`.
- `stop()` quits the loop + `controller.stop()`, joins the thread.
- `restart()` = `stop()` then `start()` (used by Apply and Re-pick).
- `save_clip()` / `toggle_record()` → `GLib.idle_add` onto the controller handlers.
- `repick_source()` clears `settings.source_restore_token` then `restart()`.
- Qt signals: `state_changed(str state, str detail)`, `clip_saved(str path)`.

**`ui/settings_form.py` — `SettingsForm(QWidget)` (unit-tested headless, offscreen Qt).**
Pure `Settings` ↔ widget mapping, no engine.
- `load(settings)` populates widgets; `collect() -> Settings` reads them back (preserving
  fields the form doesn't edit — `buffer_dir`, `source_restore_token` — by carrying the
  loaded instance forward).
- Widgets: clip length (spin), codec (combo from `EncoderRegistry().available_codecs()`),
  hardware (checkbox), bitrate (spin), fps (spin/combo), output dir (line + browse),
  audio picker (see below). `available_codecs()` and `discover_audio_devices()` are quick
  synchronous calls safe on the UI thread.

**`ui/audio_picker.py` — `AudioPicker(QWidget)` (unit-tested).**
Checkable grouped list driving `settings.audio_devices`:
- Top: "Default desktop audio" (→ `@desktop@`) and "Default microphone" (→ `@mic@`).
- Groups **Desktop (sinks)** / **Microphones** from `discover_audio_devices()`, defaults
  flagged. Checked rows write `@desktop@`/`@mic@` tokens or concrete `node_name`s, order
  preserved. Empty selection = video-only (`[]`).
- `selected_entries() -> list[str]` is the pure mapping under test (fed a fake device list).

**`ui/main_window.py` — `MainWindow(QMainWindow)` (probe/manual).**
Status indicator (colored dot + label) + `SettingsForm` + buttons: **Apply**,
**Open clips folder** (`QDesktopServices.openUrl`), **Re-pick source**. Window close hides
to tray (overrides `closeEvent`); does not quit.

**`ui/tray.py` — `TrayIcon(QSystemTrayIcon)` (probe/manual).**
Menu: Open settings · Save clip now · Toggle recording · Open clips folder · Quit.
Tooltip/icon reflect the current state.

**`ui/app.py` — `main()` (probe/manual) + `python -m tea_clipper.ui`.**
Builds `QApplication`, `EngineHost`, `MainWindow`, `TrayIcon`; wires signals; auto-starts
capture on launch; Quit stops the host and exits.

## Status state machine

`Idle → Starting → Recording`; `Recording → Restarting → Recording` (Apply / Re-pick);
any → `Error(detail)` on portal denial / encoder init failure / build exception. The window
shows a dot + label; the tray updates tooltip (and icon where practical). "Last clip saved:
`<path>`" updates from `clip_saved`, fired for **both** hotkey- and UI-triggered saves.

## Small change to `Controller`

Add an optional `clip_saved_cb` (default `None`) invoked in `_on_save_clip` and the stop
branch of `_on_toggle_record`, so clips saved **via hotkey** (on the GLib thread) surface in
the UI. `build_controller` grows an optional passthrough. Backward-compatible; existing tests
unaffected. `EngineHost` passes a callback that re-emits as the `clip_saved` Qt signal
(marshalled to the Qt thread).

## Apply / Re-pick flow

Apply: `form.collect()` → **confirmation dialog** ("Applying restarts capture; the replay
buffer resets and there's a brief gap. Continue?") → on OK: `settings.save(config)` →
`host.restart()`. Re-pick source: same confirmation, but clears `source_restore_token` first
so the portal re-prompts. Status shows `Restarting…` throughout.

## Dependency

Add **`PySide6`** as a project dependency, pip-installed into the venv like `pytest`/`tomli-w`
(`--system-site-packages` is only for PyGObject/GStreamer). Add a `[gui]`/test extra so unit
tests can import it; tests run with `QT_QPA_PLATFORM=offscreen`.

## Testing

**Unit (CI, headless offscreen Qt, no real portal/engine):**
- `SettingsForm.load`/`collect` round-trip (every edited field; untouched fields preserved).
- `AudioPicker.selected_entries()` mapping from a fake device list (tokens for defaults,
  `node_name`s for concrete, empty = `[]`, order preserved).
- `EngineHost` lifecycle with a **fake builder + fake controller**: `start()` builds + starts
  + persists token + emits `Starting`/`Recording`; `restart()` stops then starts; `save_clip`
  routes to the controller handler; `clip_saved_cb` re-emits the Qt signal; build failure →
  `Error`. (Marshalling shimmed so tests don't need a live GLib loop.)
- `Controller` `clip_saved_cb` fires on save / record-stop (extend `tests/test_controller.py`).

**Probe / manual** (`python -m tea_clipper.ui` on KDE/Wayland, AMD RDNA3): tray appears,
window opens, capture auto-starts (restore token reused), hotkeys + tray actions save clips,
status + last-clip update live, Apply restarts cleanly, Re-pick re-prompts the picker, Open
folder works. Same hardware-verification split as the existing `*_probe.py` scripts.

## Decisions

- Tray + window (Medal-style); window close hides to tray, only Quit exits.
- Save + restart on Apply, gated by a confirmation warning; Re-pick uses the same path.
- Engine on a GLib worker thread; Qt on the main thread (approach A).
- GUI is `python -m tea_clipper.ui`; the headless daemon (`python -m tea_clipper`) is kept.

## Deferred (YAGNI)

In-app log viewer, per-setting live apply (no restart), encoder/bitrate validation beyond
widget ranges, multi-monitor source selection UI, packaging/.desktop file.
